How to review component PRs

For each component listed above, review the pull requests open against its release branch. Choose which PRs to include in that component’s release. You can leave a PR undecided, exclude it, or hide it from this view. Follow the checks here and merge each included PR in GitHub.

Include tells the assistant to track the PR’s checks and merge, then verify that the selected component tag contains the merge. Exclude keeps the PR visible and stops detailed monitoring and retries. Ignore & hide also hides it from the default list. Use the Ignored & hidden filter to find it again.

With writes enabled, select Allow retry comments on an included PR to let the assistant post /konflux-retest <job> on GitHub to rerun an eligible Konflux job. In interactive mode, you approve each comment. In automatic mode, the assistant rechecks permission and eligibility before posting on its own.

{{else if eq .Tab "component-releases"}}
How to track component releases

Select the release tag for each component. If you need a new tag, follow the component’s release guide to create it and start the release, then select it here. Check that the tag covers the included PRs, follow its build status, and use Component images to see whether the CI and Konflux images have been published.

Under Build retries, you can review and copy the proposed retry comment in read-only mode. With writes enabled and permission granted for the selected tag, the assistant can post /retest <job> tag:<tag> on the tag’s commit in GitHub to retry an eligible Konflux build. In interactive mode, you approve each comment. In automatic mode, the assistant rechecks permission and eligibility before posting.
